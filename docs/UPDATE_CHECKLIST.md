- [ ] 页面无乱码、无问号替代文字、无编码错误。

## B. 数据来源（不可替换）
- [ ] 全网热点 TOP10 = 知微事见全网事件榜。
- [ ] 微博 = 微博官方热搜榜（保留排名/热度/抓取时间/链接）。
- [ ] 抖音 = 抖音官方热词榜（同上）。
- [ ] 小红书 = 小红书"问点点"可核验回答（上午"昨天…"，下午"今天…"）。

- [ ] 核心热点必须进入微博或抖音当次 TOP10；微博和抖音都纳入考虑，不只选抖音。

## C. 热点筛选与分级（硬约束）
- [ ] **核心热点最多 4 个**（新规 top6 只用于榜单展示，事件详情核心=最多4），宁可少选不凑数。
- [ ] 入选须同时满足：破圈性 + 与京东本地生活真实相关 + 可执行 + 风险可控。
- [ ] **S/A/B 分级 = 纯热点信息展示（2026-09-16 用户修正）**：S/A/B 板块只呈现热点信息，只要不是四类不展示内容，**无论能否借势都可评标**（评分 S≥85/A70-84/B55-69，按热度从高到低排序）。「能否借势」**只在本地生活业务建议板块判断**。
- [ ] **四类内容直接不展示/删除（2026-09-16 用户明确，硬性，旧"中立观察"理解已作废）**：①两性对立 ②民粹主义事件 ③动物保护（虐狗/爱狗人士）④政治（中美关系、台湾、国家领导人去世等敏感政治事件）。这四类抓到即删、不上页面任何板块、不进入 S/A/B 分级，不是"仅展示不可借势"。
- [ ] **悲剧/灾害伤亡/负面新闻等不属于四类内容 → 可进入 S/A/B 分级展示热点信息**；但**在本地生活业务建议板块明确写"不建议借势"**，不影响其评标展示。
- [ ] 排行榜颜色、事件详情、可借势清单、业务建议用**同一决策结果**，不相互矛盾。
- [ ] 颜色语义：S红/A橙/B黄/低于55仅存档灰色；台风等灾害类经审核可用对应颜色（如已确认B级台风=黄色，不得改灰）。

## D. 核心分析（必须 AI 独立推理，禁止模板）
- [ ] **事件解释 = 阐述前因后果、不复制标题（2026-09-16 用户明确，硬性）**：写清楚"谁干了什么、为什么、怎么样了"，**禁止把事件标题原样复制粘贴当解释**；也**禁止**写"官方热榜TOP1/公开热度xx/事件性强/参与度高/上热榜"这类模板噪声与热度套话；精简、像跟人讲清楚一件事。
- [ ] **为什么热度高 = 纯动因解释、无借势建议尾巴（2026-09-16 用户明确，硬性，勿再犯）**：只讲"为什么热/动因是什么"，讲真实传播动力（如公众共情/信息增量/时间节点/视觉冲击/情绪/身份/利益/冲突/参与/跨圈层），**禁止尾部加"借势须/借势宜/品牌可借"等借势建议**。参考案例：传"黑人"陈建州突发心梗 → "公众对知名人物健康的强共情与关切；突发健康事件自带即时性，舆论在'关心病情-传递祝福-讨论生活方式'间流转，情绪黏性高。"
- [ ] 事件解释 / 为什么热 / 入选理由 / 可解释 / 风险边界 → 逐条独立思考，禁止批量套用同一句式或只换热点名。
- [ ] "为什么热"讲具体传播动力（信息增量/时间节点/视觉冲击/情绪/身份/利益/冲突/参与/跨圈层），不得写"因为上热榜"。
- [ ] 无人值守定时运行必须调用配置在 Secret 的模型 API（接口/模型名/密钥不得写入代码或页面）。
- [ ] 模型输入含事件标题/平台/TOP/热度/抓取时间/链接/背景/风险/业务边界；输出结构化 `eventExplanation/whyHot/selectionReason/localLifeFit/riskBoundary`。
- [ ] 生成后必须过事实一致性、重复度、TOP10资格、风险、业务能力校验；失败不得发布。
- [ ] AI 未执行/无 API/证据不足 → 只更新原始榜单并标注"深度分析暂未生成"，**禁止模板补位冒充 AI 分析**。

## E. 玩梗模块（内容级核验）
- [ ] 玩梗回答"用户具体怎么玩"，不复述事件；不因上榜就自动称为梗。
- [ ] 进入抖音热榜对应内容，打开具体热视频，看多个创作者/评论/二次创作样本。
- [ ] 每个梗说明：起手/镜头/文案/固定结构/可替换元素/变体/模仿动机/评论区接龙。
- [ ] 只有稳定复刻 + 多人变体 + 评论区接龙才入选；围观/转发不入选。
- [ ] **玩梗卡片旁必须显示"平台TOP几 · 热度多少"+数据时间+链接**。
- [ ] **content 级：至少 3 个独立普通用户相同模板才 `confirmed_meme`；否则只 `creative_potential` 不展示；无样本/仅围观 → 整块隐藏/删除，不用普通热点补位、不沿用昨日。**
- [ ] 玩梗板块与事件详情**分别判断**，不得复用同一批结果，不查重会混。
- [ ] 不绕过登录/验证码/访问控制/平台规则。

## F. 本地生活业务建议（8 业务）
- [ ] **借势参考逻辑（2026-09-16 用户要求，硬性）**：优先从 S/A/B 级热点（核心6个）找可借势；6个里都没有再从知微top10/抖音top5/微博top5找可结合；**每条建议先写明"借势哪个热点"，再提出具体业务建议**（先指明热点 → 再给 action/comms），精简呈现。**先判断可借势/不可借**（负面/悲剧/伤亡/品牌危机→写"不建议借势"，不强行套业务）；**一条建议只借一个热点，禁止多热点混合进同一条建议**。
- [ ] **借势热点必须真实可结合业务，禁止硬凑（2026-09-17 用户强调，硬性勿犯）**：每个业务选的热点必须真正能跟该业务场景结合（如「各地进入秋季最佳赏味期」→七鲜小厨/美食MALL/外卖；「钟薛高复活」→七鲜零食；「罗永浩吐槽难吃」→七鲜品质背书）。**禁止把无关联热点硬套到业务上**（曾犯：把「美联储加息」硬套到家政/美食MALL，被用户批为"胡说八道"）。借势候选必须覆盖核心 S/A/B 热点 + **各榜单top5（抖音/微博/知微，小红书忽略）**，不要只盯核心6个漏掉榜单里真实可借的热点。**没有可借热点可不用**：某业务确实无可结合热点时就写该业务常规运营，**绝不硬凑**。
- [ ] 8 个业务（京东外卖/京东秒送/七鲜小厨/京东家政/七鲜咖啡/京东旅行/七鲜美食MALL/本地生活整体）全部按借势参考逻辑，不只外卖。
- [ ] 借势方向吸收用户 4 份业务参考文档（docs/business-reference/*.md）+ 网上可查好内容。
- [ ] 每项建议必须回答：借势判断(不适合→明确写"不建议")/借哪个热点(来自本日已审核核心)/服务谁/用户问题/具体动作/传播主线/可信证据/风险边界。
- [ ] 动作落到真实供给与履约（城市门店、商品价格库存、时间人员、配送退改售后）。
- [ ] 传播优先真实用户/订单/路线/服务/反馈，不空喊平台能力。
- [ ] 业务边界：京东外卖=品质餐厅履约；七鲜小厨=现炒食材后厨直播；七鲜咖啡=城市门店覆盖受限；京东点评真榜=真实评价不卖排名；京东旅行=核验库存退改；京东家政=自营与第三方区分；京东秒送=真实覆盖才用"最快9分钟"；七鲜美食MALL=核验城市商户动线直播。
- [ ] 灾害/伤亡/违法/品牌危机默认不做营销借势。
- [ ] 不同业务不得只换业务名复用同一套建议。
